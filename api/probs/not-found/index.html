API · Manejo de errores

404 — Recurso no encontrado

Las rutas inexistentes bajo /v1/ responden con un cuerpo JSON en formato Problem Details (RFC 9457). El campo type del error apunta a esta página.

Se aplica a toda la API bajo /v1/ Media type: application/problem+json
01

Cuerpo de la respuesta

Ante una ruta inexistente, la API responde 404 con este cuerpo, idéntico para todos los endpoints bajo /v1/:

{
  "type":    "https://pindec.dev/probs/not-found",
  "title":   "Recurso no encontrado",
  "status":  404,
  "detail":  "La ruta solicitada no existe en esta API. Los índices disponibles están en /v1/index.json.",
  "indice":  "https://pindec.dev/v1/index.json"
}

El status del cuerpo siempre coincide con el status HTTP. Un cliente JSON puede verificar el status y, si es de error, parsear el cuerpo sin ambigüedad: detail explica el motivo y indice sugiere por dónde empezar.

Fuera de /v1/, el 404 es la página HTML de error del sitio, no problem details.

02

Causas comunes

  • Error de tipeo en el indicador, la región o el período: /v1/ipc/nacional/2023/ no existe — las regiones van con inicial mayúscula (/v1/ipc/Nacional/2023/).
  • Un período aún no publicado: cada indicador cubre un rango distinto de años. El rango vigente figura en /v1/meta.json.
  • Código de clasificación inválido: los códigos admitidos por cada indicador están en el índice correspondiente (ej. /v1/ipc/index.json).
03

Cómo resolverlo

El índice general /v1/index.json lista todos los indicadores disponibles, y cada índice de indicador lista sus URLs válidas. También podés probarlas en el playground del sitio.

Si creés que una ruta válida está respondiendo 404, avisá mediante un issue en el repositorio.
